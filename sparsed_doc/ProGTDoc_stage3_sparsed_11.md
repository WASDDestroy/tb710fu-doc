## 刷写 LKM Root - 使用 9008<a id="LKMGuide_Method1"></a>

> 对 LKM 的系统版本支持请以群文件更新为主，且不支持第三方 ROM，不推荐使用。如果一定需要，请刷入群内提供的 TWRP 然后一键签名。
> 
> **重要警告：搞机有风险，流程无问题，请严格比对操作，变砖莫找群友背锅。**
> 
> 1. 强烈建议您准备一条"二代"工程线，一旦需要救砖时有大用。
> 
> 2. 如果任何步骤遇到问题，请先参考[这里](#FAQ)（条目 12），实在无法解决再向群友提问。
> 
> 3. LKM Root 需要刷写的是`vbmeta_a`和`init_boot_a`，或者`vbmeta_b`和`init_boot_b`，具体需要刷写哪两个分区根据自己机子的槽位决定，教程里有说明。
> 
> 4. 请严格按照教程来一步步操作，请不要自作聪明或者不小心将 LKM 文件组刷入错误的分区，此操作会导致你的机子变砖且很可能无法恢复。如在 Root 途中出现你不确定的问题，请及时寻求群友帮助，不要自己耍小巧思自己害死自己的机子！
> 
> 5. 刷写 Root 前请先备份！如何备份请移步[这里](#BeforeFlashing)（条目 6），你的备份十分重要，更新系统时还原`init_boot`和`vbmeta`需要用到你自己备份的`init_boot`和`vbmeta`，否则更新系统会卡系统升级安装！
> 
> 6. 此 Root 教程使用的工具为——"刷机匣"（如下图片 1），请不要使用其他工具——如"搞机助手"（如下图片 2）等其它工具，使用其他工具出问题者我们不会提供相关帮助（如救砖），届时请自己解决。

> 下面的教程均建立在你安装好了 9008 驱动的前提下，如果你不会安装，跳转到 [安装驱动](#Install_Driver) 进行学习。



自己下载群文件夹中合适的文件：

1. 刷机工具：刷机匣，位于"搞机工具"文件夹中；
2. 镜像文件压缩包（带 LKM 字样）：选择 KernelSU 文件夹中的 7z 文件（单个压缩包大小为 10MiB 以内），并请注意文件末尾的版本号数字，您应当使用与自己的平板当前运行的 ZUXOS 版本号一致的文件；
3. Root 管理器：根据你使用的镜像自行选择。

![](./media/image42.png)

**Step 1**: 作者设备运行的 ZUXOS 版本为 326，因此下载群文件中的`kernelsu_lkm_12123_326.7z`。把其中的文件解压缩到方便找到的目录，例如`D:\LKM`

![](./media/image43.jpg)

**Step 2**: 现在将设备重启到 9008 模式：关机，按住音量加，并插入数据线，设备应当先显示充电符号，并在几秒钟后黑屏，且电脑发出插入设备的提示音。这时可以松开音量键，准备在电脑端发送引导。

> 如果无法进入，将平板开机，[打开 USB 调试](#USB_Debugging)，电脑上[安装 ADB](#Install_ADB)，然后在电脑上输入命令`adb reboot edl`即可进入 9008 模式。

发送引导方式：

1. 点击"选择设备/引导/配置"

![](./media/image44.png)

2. 在弹出的窗口中，点击"引导文件"处右侧的"..."按钮，并在弹出的对话框选择从群文件夹"神秘引导文件"下载的`xbl_s_devprg_ns.melf`文件，并点"打开"选择它，最后在刷机匣的对话框点击确认。

![](./media/image45.png)

![](./media/image46.png)

3. 现在回到刷机匣的主界面，点击"读信息"，确认一下设备连接是否正常，如果正常，应当能够读取到分区信息。

![](./media/image47.png)

![](./media/image48.jpg)

> Note: 日志内有上图所示的错误信息是正常的

**Step 3**: 如果您此前未使用 GKI 镜像进行 Root，请跳转到[**Step 4**](#LKM_Step4)；反之，请跟随本步骤操作。<a id="UnRoot_GKI"></a>

1. 使用工具箱的"槽位功能/查看槽位"确认活动槽位，记住槽位号。
   ![](./media/image49.png)

2. 如果槽位为 A，找到`boot_a`分区，反之，找到`boot_b`分区，并勾选分区前的复选框，然后选择之前备份的原`boot`分区文件，如果没有备份，可以尝试群文件夹"香香软软的原始 BOOT 文件"中的内容，请同样注意槽位号
   ![](./media/image50.png)

3. 现在，点击"刷入"，恢复原始`boot`镜像
   ![](./media/image51.png)

4. **点击“槽位功能”中的“重设当前槽位”**
   ![](.//media/image59.png)

5. 完成后重启设备至系统（如果无法正常启动请看下一步），确认 Root 管理器中工作状态变为"未安装"即完成恢复步骤

![](.//media/image52.png)

**Step 4**: 现在可以准备正式刷入`vbmeta`和`init_boot`了，先**备份对应分区。**<a id="LKM_Step4"></a>

> 如果您刚刚完成步骤 3，请按步骤 2 方法重新将设备重启至 9008 模式并发送引导，然后继续操作。

勾选正确槽位的`init_boot`和`vbmeta`两个分区后，按右侧的回读按键从设备读出分区，记得选择容易记忆且有区分度的目录，例如作者选择将回读的文件存储在`D:\LKM\Readback`中。

![](./media/image54.png)

![](./media/image55.png)

![](./media/image56.png)

**Step 5**: 正式刷入`init_boot`和`vbmeta`，为两个分区选择对应的、已经过 Root 管理器修补并利用`avbtool.py`签名的文件，并点按刷入按钮

![](./media/image57.png)

![](./media/image58.png)

**Step 6**: 点击刷机匣右侧界面"更多功能"里的"槽位功能"，然后**点击"重设当前槽位"**，如下图；

![](./media/image59.png)

完成上述步骤后，在刷机匣找到如下图选项，点击重启->系统即可重启到系统界面，开机后安装和所用镜像匹配的 Root 管理器（例如刷入的是 KernelSU 的镜像就安装 KernelSU 的管理器，其他同理），完成全流程。

![](./media/image38.png)

**Step 7**: 设备应当正确启动。启动后请安装合适的 Root 管理器（例如作者使用 KernelSU LKM, 那么安装 KernelSU），此时应当看到管理器中显示工作中\<LKM>，如下图所示：

![](./media/image60.png)

**Step 8**: 确认管理器处于工作中后请关闭管理器中的"检查更新"选项，位置位于"设置-检查更新"，请参考下图

![](./media/image40.png) ![](./media/image61.png)
